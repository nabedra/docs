## Reproduce scheduler measurements

Run the local OLAP fixtures sequentially with other test load stopped. Use fresh output paths.

```bash
export CARGO_BUILD_JOBS=2 CARGO_PROFILE_DEV_DEBUG=0 CARGO_PROFILE_TEST_DEBUG=0 CARGO_INCREMENTAL=0
cargo build --locked --manifest-path server/Cargo.toml --no-default-features \
  --features olap --bin nabedra-db --example resource_scheduler_benchmark
mkdir -p artifacts
server/target/debug/examples/resource_scheduler_benchmark \
  --output artifacts/scheduler-pool-benchmark.json
python3.11 scripts/acceptance_scheduler_load.py --binary server/target/debug/nabedra-db \
  --suite benchmark --output artifacts/scheduler-http-benchmark.json
python3.11 scripts/summarize_scheduler_benchmarks.py \
  --pool artifacts/scheduler-pool-benchmark.json --http artifacts/scheduler-http-benchmark.json \
  --output artifacts/scheduler-benchmark-evidence.json
```

The historical scheduler run used an unoptimized development build, loopback TCP, a local SQLite-backed conditional object store, and a synthetic read delay. Check the fixture's request mix, concurrency, and host limits before comparing it with S3 or a different build.
