---
title: "Troubleshooting"
description: "Diagnose startup, authentication, admission, and recovery failures."
---

| Symptom | Check |
| --- | --- |
| A database command or stream route is unavailable | Run `--version` and `--help` with the path to the `nabedra-db` executable you used to start the server. Check [package support](/guides/installation#package-and-checkout-support) for your feature, including the [OLAP streaming preview](/python/streaming). |
| Server fails to start or readiness fails | Inspect server logs and verify the configured catalog, mounted store or worker readiness. For S3, check the region, bucket, prefix, and [permissions](/server/configuration#s3-permissions). Readiness alone does not verify writes. |
| `401 unauthorized` | Check the endpoint URL, bearer token and database selector. Data, cluster admin, gateway and Events tokens belong to different interfaces. |
| TLS verification fails | Confirm that the hostname matches the certificate and supply the private CA with `ca_file` or `curl --cacert` when needed. |
| `404 not_found` for an existing table name | Fetch the table again by name. A dropped and recreated table has a new ID, so old handles remain stale. |
| Database reports `409 conflict` | Check the error message for a duplicate table name, duplicate primary key, or request identity conflict. When [recovering a queued submission in the same run](/python/receipts#recovery-and-retention), reuse the original UUID and exact body. An ordinary ORM call generates a new UUID. |
| `413 limit_exceeded` | Reduce the insert batch, select fewer columns, or use a smaller query limit. For an OLAP stream, reduce `batch_rows`. |
| Database reports `429 overloaded` with outcome `not_applied` before acceptance | Reduce concurrent submissions and check eligible ready workers and [queue capacity](/server/worker-runtime). Retry after capacity is available. |
| A database write times out or reports outcome `unknown`, including some `429 overloaded` responses | Save the original request ID and any known run ID. Follow [uncertain write recovery](/python/errors#resolve-an-uncertain-write) before submitting another write. |
| A receipt or stream disappeared on restart | Check whether the worker run changed and whether the retention window elapsed. A full shutdown abandons outstanding RAM work. Only committed mutation decisions are durable. |
| Events reports an unknown publish outcome | [Retry the same publish](/events/python-client#publish-events) while the original event would still be retained. If retention may have elapsed, check your application's records before publishing again. |
| Events reports `lease_lost` | [Claim the subscription partition again](/events/python-client#claim-and-consume-a-subscription), then poll with the new lease to resume from the saved checkpoint. |
| Events reports `checkpoint_expired` | Check the earliest available offset in the error and follow the [operator recovery procedure](/events/broker#recover-an-expired-checkpoint). |

For an OLAP cluster, `nabedra-db doctor --config PATH --json` checks local configuration and protected auth paths and probes a control object. Check `storage_read` in its report. The probe leaves write access unverified. Use the [matching Python CLI](/guides/installation#install-the-cli-and-server-together) to run `nabedra database cluster status --url URL --admin-token-file PATH` and inspect enrollment and worker capacity.
