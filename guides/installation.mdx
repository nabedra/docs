Install the Python client from PyPI and the OLAP server from crates.io. If you already have a running server, install the client and [connect from Python](/python/connect).

## Install the Python package

Use Python 3.11 or newer. Run these commands from your project directory, substituting your Python executable if needed.

```bash
python3.11 -m venv .venv
.venv/bin/python -m pip install --upgrade nabedra
.venv/bin/python -m pip show nabedra
```

The core package uses the Python standard library. For optional integrations, install `'nabedra[gateway]'` for HTTPX or `'nabedra[aws]'` for Boto3. The `database` extra adds no dependencies. [PyPI package](https://pypi.org/project/nabedra/)

## Install the native server

Use Rust 1.94.1 or newer with Cargo and a C compiler and linker. On Debian, install `build-essential`. On macOS, install the Xcode command line tools. Run the same command to upgrade an existing Cargo installation.

```bash
cargo install nabedra-database --locked
nabedra-db --version
```

Cargo installs `nabedra-db`, typically in `~/.cargo/bin`. Add the Cargo bin directory to your `PATH` if the shell cannot find the executable. The default build uses OLAP with S3. Follow the [quickstart](/guides/quickstart) to start it. [Crates.io package](https://crates.io/crates/nabedra-database)

## Package and checkout support

| Component | Published package | Features available from the source archive |
| --- | --- | --- |
| Native server | `nabedra-database` for OLAP with S3 | [Local OLTP](/server/oltp), [OLAP streaming](/python/streaming), and [offline data interchange](/operations/backup-and-migration#move-olap-tables-to-oltp) |
| Python | `nabedra` for the ORM and gateway | Launcher support for `nabedra-db`, [streaming and Arrow](/python/streaming), the [Events client](/events/python-client), and [OLTP deployment adapters](/operations/oltp-deployment#provider-integrations) |
| Events broker | Unpublished | [Broker and Docker fixture](/events/broker) and [AWS Terraform configuration](/events/aws) |

For a server installed with Cargo, run `nabedra-db serve` directly. The current PyPI launcher checks for the former executable name, `nabedra-database-server`. For `nabedra database serve`, [install the CLI and server together](#install-the-cli-and-server-together).

## Download the source archive

For a feature that still needs source, use `curl` and `tar` to download and extract the latest `main` archive. Keep using the same shell so `$nabedra_source` points to the extracted files.

```bash
nabedra_download="$(mktemp -d)"
nabedra_source="$nabedra_download/source"
mkdir "$nabedra_source"
curl -fLsS https://github.com/zPy52/nabedra-database/archive/refs/heads/main.tar.gz \
  -o "$nabedra_download/nabedra-database.tar.gz" &&
  tar -xzf "$nabedra_download/nabedra-database.tar.gz" \
    --strip-components=1 -C "$nabedra_source"
```

The archive follows development on `main`. Use the same download for components you plan to run together.

## Install a preview server

Start with the [native server build prerequisites](#install-the-native-server). For OLTP, also install a C++ compiler, CMake, and libclang for RocksDB. On Debian, install `build-essential cmake clang libclang-dev`. On macOS, make CMake and libclang available to the compiler and bindgen.

From your working directory, use the [extracted source archive](#download-the-source-archive). Choose one engine. Each command uses a separate installation directory so both binaries can coexist.

<CodeGroup>

```bash OLTP
cargo install --locked --path "$nabedra_source/server" \
  --no-default-features --features oltp --root "$PWD/.nabedra-oltp"
./.nabedra-oltp/bin/nabedra-db --version
```

```bash OLAP with S3
cargo install --locked --path "$nabedra_source/server" --root "$PWD/.nabedra-olap"
./.nabedra-olap/bin/nabedra-db --version
```

</CodeGroup>

Check that the version output includes the engine you selected. For OLTP, follow [Run local OLTP](/server/oltp). Use the OLAP archive build for [streaming](/python/streaming) and [offline export](/operations/backup-and-migration#move-olap-tables-to-oltp).

The default source build selects `olap,s3`. Use `--no-default-features --features olap` for OLAP without AWS dependencies or `--no-default-features --features oltp-backup-s3` for OLTP with optional S3 backups. Cargo builds require exactly one engine.

## Install the CLI and server together

Use Python 3.11 or newer and the [native server build prerequisites](#install-the-native-server) on Linux or macOS. [Download the source archive](#download-the-source-archive), then run these commands from your project directory with a new installation prefix.

```bash
python3.11 "$nabedra_source/scripts/install_nabedra.py" --prefix "$PWD/.nabedra"
./.nabedra/bin/nabedra --version --json
source .nabedra/bin/activate
```

The installer defaults to OLAP with S3. It honors `CARGO_TARGET_DIR`. For OLTP, install the [OLTP build prerequisites](#install-a-preview-server), use `--engine oltp` with a separate prefix, and add `--with-s3` if you need S3 backups. When set, `NABEDRA_SERVER_BINARY` selects the executable. Otherwise the launcher checks its Python environment and then `PATH`. Use [cluster setup](/server/clusters) to configure a supervised OLAP server.

## Build a container image

Use the [extracted archive](#download-the-source-archive) as the Docker build context.

<CodeGroup>

```bash OLAP
docker build --build-arg NABEDRA_ENGINE=olap -t nabedra:olap "$nabedra_source"
```

```bash OLTP
docker build --build-arg NABEDRA_ENGINE=oltp -t nabedra:oltp "$nabedra_source"
```

</CodeGroup>

The OLAP image runs the Python CLI, and the OLTP image runs `nabedra-db`. Use `--build-arg NABEDRA_S3=true` or `false` to override the S3 default. [Dockerfile](https://github.com/zPy52/nabedra-database/blob/1418bad88e1df1b8c868b88889a120e37059c1c0/Dockerfile)
