---
title: "Build a task tracker"
description: "Create, query, update, and reopen an OLAP table using Python and S3."
---

Create a task table, query it by priority, and check that updates survive a server
restart. You need Python 3.11 or newer, Rust 1.94.1 or newer with Cargo,
curl, and an existing S3 general purpose bucket. Run the shell commands from the
root of the [documented source checkout](https://github.com/zPy52/nabedra-database/tree/1418bad88e1df1b8c868b88889a120e37059c1c0).
Use your Python executable in place of `python3.11` if you have a newer version.

<Steps>
<Step title="Install the client and build the server">

```sh
python3.11 -m venv .venv
.venv/bin/python -m pip install -e ./orm/python
cargo build --locked --manifest-path server/Cargo.toml --bin nabedra-db
server/target/debug/nabedra-db --version
```

The version should include `olap`. The default build includes S3 support.

</Step>
<Step title="Configure and start the server">

In terminal 1, use an AWS identity with `s3:ListBucket` on the bucket and
`s3:GetObject` and `s3:PutObject` on objects under the tutorial prefix.
Replace the region and bucket placeholders and choose a long, random token
made of ASCII letters and digits. Set `AWS_PROFILE` if you use a named profile.
See [S3 permissions](/server/configuration#s3-permissions).

```sh
export AWS_REGION='<bucket-region>'
export NABEDRA_S3_BUCKET='<existing-bucket>'
export NABEDRA_S3_PREFIX="task-tracker-$(.venv/bin/python -c 'import uuid; print(uuid.uuid4().hex)')/"
export NABEDRA_TOKEN='<your-private-bearer-token>'
server/target/debug/nabedra-db serve --host 127.0.0.1 --port 8000
```

The generated prefix gives this run its own database. Keep this terminal open
so you can restart the server with the same environment.

In terminal 2, check that the server can read its catalog. The probe prints
`200` on success. If it fails, check the server logs and the
[bucket, prefix, and credentials](/operations/troubleshooting).

```sh
curl --fail --silent --show-error --write-out '%{http_code}\n' http://127.0.0.1:8000/health/ready
```

</Step>
<Step title="Connect and create a table">

In terminal 2, set the same bearer token and start Python. Your client needs
the token and server URL. The server uses the AWS credentials.

```sh
export NABEDRA_TOKEN='<same-token-as-terminal-1>'
.venv/bin/python
```

Run the Python blocks in this session, in order.

```python
import uuid
from nabedra import Database, col

db = Database(url="http://127.0.0.1:8000", mode="olap")
table_name = "tutorial_tasks_" + uuid.uuid4().hex
tasks = db.create_table(
    table_name,
    {"id": str, "title": str, "priority": int, "done": bool},
    key="id",
)
print(tasks.name)
print(tasks.schema)
```

Save the printed name to reopen this table from a new Python session. The
schema makes `id` the unique primary key and requires all four columns on
inserts. See [tables and rows](/python/tables) for supported types.

</Step>
<Step title="Insert and retrieve tasks">

```python
inserted = tasks.insert_many([
    {"id": "t1", "title": "Read the guide", "priority": 1, "done": True},
    {"id": "t2", "title": "Build a demo", "priority": 3, "done": False},
    {"id": "t3", "title": "Write tests", "priority": 2, "done": False},
])
assert inserted == 3

print(tasks.get("t2"))
# {'id': 't2', 'title': 'Build a demo', 'priority': 3, 'done': False}

assert tasks.get("missing") is None
```

`insert_many` writes one atomic batch. A duplicate key in the batch or the
table rejects the whole batch.

</Step>
<Step title="Filter and query the table">

```python
open_tasks = tasks.where(done=False)
urgent = open_tasks.where(col("priority") >= 2)
query = urgent.select("id", "title").order_by("priority", desc=True).limit(10)

rows = query.collect()
assert rows == [
    {"id": "t2", "title": "Build a demo"},
    {"id": "t3", "title": "Write tests"},
]
print(rows)
assert query.count() == 2
print(query.explain())
```

Each builder returns a new query, so you can reuse `open_tasks` with other
filters. The server sorts on `priority` before selecting the result columns.
`collect()` and `count()` each read a fresh committed snapshot, and
`explain()` reports the plan from metadata.

To combine comparisons, put each comparison in parentheses and use `&` for
AND, `|` for OR, and `~` for NOT.

```python
matches = tasks.where((col("priority") >= 2) & (col("done") == False))
assert matches.count() == 2
```

See [queries and expressions](/python/queries) for ordering and count rules.

</Step>
<Step title="Update, replace, and delete rows">

```python
updated = tasks.update("t2", {"done": True})
assert updated is True
assert tasks.get("t2")["title"] == "Build a demo"

tasks.upsert({
    "id": "t3", "title": "Write integration tests", "priority": 3, "done": False,
})

deleted = tasks.delete("t1")
assert deleted is True
assert tasks.get("t1") is None
assert tasks.query().count() == 2
```

`update` changes the supplied non-key columns. `upsert` takes a complete row
and replaces the row with that key or inserts it if the key is new. Each call
commits separately.

</Step>
<Step title="Restart and reopen the table">

Leave Python open in terminal 2. In terminal 1, press Ctrl+C and wait for the
server to exit. Keep the same bucket, prefix, and token, then restart with
`--cold-start`. The flag starts a fresh request queue and preserves committed
data. See [worker recovery](/server/worker-runtime#admission-and-recovery)
for what happens to in-flight requests.

```sh
server/target/debug/nabedra-db serve --host 127.0.0.1 --port 8000 --cold-start
```

Rerun the readiness probe in a third terminal, then run this in the same Python session.

```python
reopened = db.table(table_name)
assert reopened.id == tasks.id
assert reopened.query().count() == 2
assert reopened.get("t1") is None
assert reopened.get("t2")["done"] is True
assert reopened.get("t3")["title"] == "Write integration tests"
print(reopened.name)
```

Passing assertions confirm that the table ID and row changes survived the restart.
In a new session, connect with the same URL and token and pass the printed name
to `db.table(name)`.

</Step>
<Step title="Handle errors and storage limits">

Inserting another row with key `t2` raises `ConflictError`. The exception
reports the server error code, request ID, and outcome.

```python
from nabedra import ConflictError

try:
    reopened.insert({"id": "t2", "title": "Duplicate", "priority": 1, "done": False})
except ConflictError as error:
    print(error.code, error.request_id, error.outcome)
```

Press Enter on a blank line to finish the `try` block in the Python prompt.
Expect `conflict`, a request UUID, and `not_applied`. If a write raises
`UnknownOutcomeError`, it may still commit. Keep the request ID and follow
[recovery for uncertain writes](/python/errors#resolve-an-uncertain-write)
before submitting another write.

For an oversized query result, select fewer columns or use a smaller limit.
If ascending primary-key order works for your query, you can also
[stream OLAP batches](/python/streaming). See [database limits](/reference/limits#database)
for the request, result, and table caps.

</Step>
<Step title="Finish the tutorial">

To remove the table from the catalog, run this optional step in Python.

```python
reopened.drop()
```

Dropping the table leaves its Parquet snapshots in S3. Leave the table in the
catalog if you plan to reopen it again. To stop the server, press Ctrl+C in
terminal 1 and wait for the process to exit.

</Step>
</Steps>
